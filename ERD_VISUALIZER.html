مخطط العلاقات وقواعد البيانات (ERD) ومنطق الارتباط

المخطط المعماري الكامل لقاعدة بيانات Catalog في Django. يشرح بدقة الأسباب الهندسية والأمنية خلف كل علاقة واحد-لمتعدد، واحد-لواحد، ومتعدد-لمتعدد.

  • بدون بوابة SMS (رموز OTP عبر البريد الإلكتروني)
  • بدون بوابة دفع خارجية (باقات معرفية توضيحية)
  • بدون مهام غير متزامنة / Workers (تقييم فوري عند الطلب)
  • خزانة رسائل مشفرة بنظام AES-256-GCM

منطق ودرجة العلاقات (Cardinality) مع التبرير المعماري

شرح تفصيلي لكل علاقة ولماذا تم اختيار هذا النموذج لحماية سلامة البيانات والأمان وسير العمليات.

User Message

1 : N واحد لمتعدد

المفتاح الأجنبي: Message.sender_id

لماذا علاقة واحد لمتعدد (1 : N)؟

ينشئ المستخدم رسائل متعددة عبر سنوات حياته (نصائح ووصايا للأبناء، رسائل زفاف، تذكيرات للذات المستقبلية). كل رسالة لها مؤلف/مرسل فريد واحد فقط يمتلك المحتوى ومفتاح تشفيره وإدارته.

User Contact

1 : N واحد لمتعدد

المفتاح الأجنبي: Contact.owner_id

لماذا علاقة واحد لمتعدد (1 : N)؟

يمتلك كل مستخدم دفتر عناوين خاص ومستقل من جهات الاتصال (الأم، الزوجة، الأصدقاء، جهة موثوقة). جهات اتصال المستخدم (أ) خاصة تماماً ومعزولة برمجياً، ولا يجوز تسريبها أو إظهارها في قائمة جهات اتصال المستخدم (ب).

User InactivitySettings

1 : 1 واحد لواحد

مفتاح رئيسي وأجنبي معاً: user_id

لماذا علاقة واحد لواحد (1 : 1)؟

يمتلك المستخدم إعدادات واحدة وحصرية لآلية "مفتاح الرجل الميت" (فترة تكرار التحقق، مهلة السماح الاحتياطية، والجهة الموثوقة المعينة). فرض علاقة 1:1 يمنع أي تعارض في السياسات أو الحالات المتناقضة للملف الشخصي الواحد.

Message Delivery

1 : N واحد لمتعدد

المفتاح الأجنبي: Delivery.message_id

لماذا علاقة واحد لمتعدد (1 : N)؟

فصل حالات المستلمين الحاسم: عند توجيه رسالة إلى 3 أشخاص، يمر كل مستلم بدورة حياة تسليم مستقلة تماماً (مستلم فتحها فوراً، ومستلم آخر اختار "الفتح لاحقاً"، وآخر لم يفتحها بعد). كما يتطلب كل مستلم رمز رابط عام آمن وخاص به (access_token_hash).

Message MessageMedia

1 : N واحد لمتعدد

المفتاح الأجنبي: MessageMedia.message_id

لماذا علاقة واحد لمتعدد (1 : N)؟

يمكن للرسالة الواحدة أن تتضمن عدة مرفقات وسائط (مثل: تسجيل صوتي + صورتين + مقطع فيديو). فصل المرفقات في جدول مستقل يتيح تتبع تقدم الرفع، وحساب المساحة التخزينية المستهلكة، وإنشاء روابط موقعة مؤقتة دون تضخيم سجل الرسالة الأساسي.

Message Contact

N : M متعدد لمتعدد

جدول الربط: MessageRecipient (message_id, contact_id)

لماذا علاقة متعدد لمتعدد (N : M)؟

يمكن توجيه الرسالة الواحدة لعدة أفراد في آن واحد، كما يمكن لنفس جهة الاتصال (مثل: "الأم") أن تتلقى عدة رسائل مميزة من المستخدم عبر سنوات ومناسبات مختلفة طوال فترة استخدام الخدمة.

User Device

1 : N واحد لمتعدد

المفتاح الأجنبي: Device.user_id

لماذا علاقة واحد لمتعدد (1 : N)؟

يستطيع المستخدم تسجيل الدخول واستخدام التطبيق من أجهزة متعددة (مثل آيفون، آيباد، وجهاز لوحي آخر). إشعارات التحقق اللحظية (FCM) الخاصة بنظام إثبات الحياة ("أين أنت؟ هل أنت بخير؟") يجب أن تصل لجميع الأجهزة النشطة في نفس اللحظة لضمان وصول التنبيه.

User OTPCode

1 : N واحد لمتعدد

المفتاح الأجنبي: OTPCode.user_id (يقبل فارغ)

لماذا علاقة واحد لمتعدد (1 : N)؟

يطلب المستخدم رموز تحقق في مراحل زمنية وأغراض مختلفة (تأكيد البريد، إعادة تعيين كلمة المرور، أو فتح الرسالة للمستلم). كل رمز يمثل حدثاً مستقلاً بصلاحية 5 دقائق وعداد محاولات أمان لمنع هجمات التخمين.

User Checkin

1 : N واحد لمتعدد

المفتاح الأجنبي: Checkin.user_id

لماذا علاقة واحد لمتعدد (1 : N)؟

يرسل نظام إثبات الحياة استفسارات دورية للمستخدم. على مدار الأشهر والسنوات، يتفاعل المستخدم بنقر "أنا بخير" عشرات المرات. نحتفظ بسجل تاريخي غير قابل للتعديل لتوثيق كل استجابة ومنع أي خطأ أو إطلاق غير مقصود للرسائل.

User TrusteeConfirmation

1 : N واحد لمتعدد

المفتاح الأجنبي: TrusteeConfirmation.user_id

لماذا علاقة واحد لمتعدد (1 : N)؟

عند انقطاع المستخدم، يُرسل طلب تأكيد للجهة الموثوقة. إذا عاد المستخدم لاحقاً وألغى الإجراء ثم انقطع مجدداً في وقت لاحق، تبدأ دورة تأكيد جديدة كلياً برمز توكن ورقم IP وسجل قرار مستقل تماماً.

Plan User

1 : N واحد لمتعدد

المفتاح الأجنبي: User.current_plan_id

لماذا علاقة واحد لمتعدد (1 : N)؟

باقة الاشتراك (المجانية، الشهرية، باقة الشركات) هي نموذج عام يحدد الحدود والمزايا (مثل max_messages، storage_years). يشترك آلاف المستخدمين في نفس الباقة، ولكن كل مستخدم يرتبط بباقة نشطة واحدة في الوقت ذاته.

Contact User

N : 1 متعدد لواحد (اختياري)

المفتاح الأجنبي: Contact.linked_user_id (يقبل فارغ)

لماذا علاقة متعدد لواحد (N : 1)؟

إذا تطابق البريد الإلكتروني لجهة الاتصال مع حساب مسجل في التطبيق، يتم ربطه تلقائياً لتظهر الرسائل الواردة مباشرة في صندوق الوارد الداخلي /inbox. يمكن لعدة مستخدمين حفظ نفس الشخص كجهة اتصال لديهم بشكل مستقل.

تفاصيل الجداول الشاملة في قاعدة البيانات

التحليل الوظيفي، معايير أمان البيانات، والعلاقات الصادرة والواردة لكل جدول أساسي.

User

الهوية الأساسية

الدور والوظيفة في Catalog

يمثل الملف الشخصي الأساسي للمستخدم، ويدير المصادقة، ومفاتيح التشفير، ونبضات النشاط. يتم تحديث حقل last_active_at مع كل طلب API ونقرة "أنا بخير"، مما يشغل محرك إثبات الحياة عند الطلب دون الحاجة لجدولة مهام خلفية مستمرة.

  • Message (sender_id) 1 : N

    لماذا 1 لمتعدد: ينشئ المستخدم رسائل متعددة؛ وكل رسالة ترتبط بمرسل واحد فقط.

  • Contact (owner_id) 1 : N

    لماذا 1 لمتعدد: يمتلك المستخدم قائمة جهات اتصال خاصة ومستقلة.

  • InactivitySettings (user_id) 1 : 1

    لماذا 1 لواحد: يمتلك المستخدم إعدادات واحدة وحصرية لآلية التحقق من الحياة.

Message

خزانة الرسائل المشفرة

الدور والوظيفة في Catalog

يخزن الرسائل المكتوبة وشروط إطلاقها (فوري، تاريخ محدد، مناسبة، أو انقطاع النشاط). لضمان الخصوصية القصوى، تُشفر نصوص الرسائل بخوارزمية AES-256-GCM (body_encrypted, body_iv, body_tag) ولا تُفك شفرتها إلا عند عرضها من قبل المرسل أو المستلم المعتمد.

  • MessageMedia (message_id) 1 : N

    لماذا 1 لمتعدد: يمكن أن تحتوي الرسالة على مرفقات صوتية وصور وفيديو متعددة.

  • Delivery (message_id) 1 : N

    لماذا 1 لمتعدد: يمتلك كل مستلم دورة حياة تسليم مستقلة وحالة فتح ورابط عام آمن خاص به.

Delivery

حالة ومسار التسليم

الدور والوظيفة في Catalog

يتتبع مسار تسليم الرسالة لكل مستلم على حدة (في الانتظار → أُرسلت → تم التسليم → فُتحت). يحتوي على access_token_hash (تجزئة SHA-256 لرمز آمن عشوائي بطول 32 بايت) الذي يشغل الرابط العام للمستلم (/r/:token).

  • Message (message_id) N : 1

    لماذا متعدد لواحد: عمليات تسليم متعددة تنبثق من رسالة واحدة موجهة لعدة مستلمين.

  • Contact (contact_id) N : 1

    لماذا متعدد لواحد: تستقبل نفس جهة الاتصال عدة رسائل عبر فترات متباعدة.

InactivitySettings

محرك إثبات الحياة

الدور والوظيفة في Catalog

يضبط إعدادات مفتاح الأمان عند الانقطاع: المدة بين الفحوصات، الحد الأقصى للفحوصات الفائتة، فترة السماح الاحتياطية، وجهة الاتصال الموثوقة المعينة. الحالات: نشط → تحذير → بانتظار الموثوق → تم الإطلاق.

  • User (user_id PK=FK) 1 : 1

    لماذا 1 لواحد: يمتلك كل مستخدم إعدادات أمان واحدة لحسابه فقط.

  • Contact (trustee_contact_id) N : 1 اختياري

    لماذا متعدد لواحد: يختار المستخدم جهة اتصال واحدة على الأكثر من دفتر عناوينه للتحقق من سلامته.
